# ledger-and-report.md —— 台账与日报格式（jobhunt-daily 第 6/7 步用）

> **台账（`02-jobs/job-ledger.csv`）是唯一事实源**：日报、周报都从台账生成，不另立事实源。
> 台账是 CSV 文件（逗号分隔的纯文本表格）：字段里**不要出现英文逗号**，需要停顿用中文逗号或顿号。

## 一、job-ledger.csv 表头（固定，一字不差）

```csv
id,date_added,company,position,source,city,salary_range,jd_file,match_grade,status,last_action,next_step,notes
```

各列记法：

| 列 | 记法 |
| --- | --- |
| id | `J-YYYYMMDD-序号`（如 J-20250717-001），全表唯一，生成后不变 |
| date_added | 入台账日期，YYYY-MM-DD |
| company | 公司名（简称即可，全表口径一致） |
| position | 岗位名（以 JD 原文为准） |
| source | 枚举：**boss / liepin / linkedin / lagou / 官网 / 内推 / 猎头 / 其他** |
| city | 工作城市（JD 原文为准） |
| salary_range | JD 标注的薪资区间，原文照抄（如"面议"或 JD 写的区间），不做换算 |
| jd_file | JD 原文存档路径 `02-jobs/jd/<company>-<role>.md`；没存档留空 |
| match_grade | 枚举：**⭐ / ⭐⭐ / ⭐⭐⭐**（命脉卖点强对口 = ⭐⭐⭐）；未评 = 空 |
| status | 见下方流转图 |
| last_action | 最近一次动作 + 日期（如"2025-07-17 已投递（用户手动投）"） |
| next_step | 下一步动作（如"等 HR 回复""周五前跟进"） |
| notes | 备注（淘汰原因、"JD 信息不足"、定制简历路径等） |

**去重键 = company + position**：同一公司同一岗位只一行。再遇到只更新 status / last_action / next_step，不新建行、不重复投。

## 二、status 枚举与流转图

```
已收藏 → 待投递 → 已投递 → 被查看 → 沟通中 → 面试中 → offer（终态）
                          │           │          │
                          └───────────┴──────────┴→ 对方已拒 / 已放弃 / 已结束（终态）
```

- 状态只按箭头往前走；终态四个：**offer / 对方已拒 / 已放弃 / 已结束**（岗位下架、流程终止等）。
- 「待投递」= 过筛通过、在待确认清单里等用户拍板；用户手动投完或 CLI 投完才推进到「已投递」。
- 跳变允许（如已收藏直接对方已拒——岗位下架），但要在 notes 记一句原因。

## 三、记法示例（两行，照此格式）

```csv
id,date_added,company,position,source,city,salary_range,jd_file,match_grade,status,last_action,next_step,notes
J-20250717-001,2025-07-17,某科技公司,后端工程师,boss,杭州,JD标注区间,02-jobs/jd/某科技公司-后端工程师.md,⭐⭐,已投递,2025-07-17 已投递（用户确认后手动投）,等 HR 查看 三天无动静跟进,命脉卖点部分对口
J-20250717-002,2025-07-17,某互联网公司,平台产品经理,liepin,上海,面议,,⭐,已收藏,2025-07-17 收藏 待补 JD,请用户补 JD 全文后复核评级,JD 信息不足
```

## 四、日报模板（`runtime/reports/YYYY-MM-DD.md`；有 lark-cli 则同步飞书云文档）

**从台账当天数据生成**，写完把本地路径或飞书链接回给用户。固定三块 + 一个提醒：

```markdown
# 求职日报 YYYY-MM-DD

## 今日概况

- 新增岗位：N（boss N / 猎聘 N / 其他 N）
- 初筛通过：N（⭐⭐⭐ N / ⭐⭐ N / ⭐ N）；淘汰 N（主要原因：一句话）
- 待用户确认：N
- 已投递：N（CLI 投 N / 用户手动投 N）
- 面试推进：N（公司名 + 进展一句话；没有写"无"）

## 岗位明细

| 公司 | 岗位 | 评级 | 状态 | 下一步 |
| --- | --- | --- | --- | --- |
| 某科技公司 | 后端工程师 | ⭐⭐ | 已投递 | 等 HR 查看 |

## 待用户确认清单（拍板后 AI 或用户执行）

| 公司 | 岗位 | 评级 | 建议动作 |
| --- | --- | --- | --- |
| 某互联网公司 | 平台产品经理 | ⭐⭐⭐ | 先走 resume-tailor 定制再投 |

## 待定决策提醒

- （引用 CONTEXT.md「待定决策清单」里被今天进展触动的事项；没有写"无"）
```

纪律：日报只写对外可见的事实与数字；`_internal/` 内容（薪资底线、真实离职原因、短板应对）**不进日报**。

## 五、周报模板（`runtime/reports/YYYY-Www.md`，每周日从台账生成）

```markdown
# 求职周报 YYYY 第 ww 周（MM-DD ~ MM-DD）

## 本周漏斗（台账状态计数，逐级转化率）

已收藏 N → 已投递 N（转化 N%）→ 被查看 N（N%）→ 沟通中 N（N%）→ 面试中 N（N%）→ offer N（N%）

- 断点分析：哪一级掉得最多？可能原因一句话（评级过松/简历不对口/搜索词偏了）。

## 分方向进展

| 方向 | 新增 | 投递 | 沟通/面试 | 结论一句话 |
| --- | --- | --- | --- | --- |

## 下周策略调整建议

- 搜索词调整：（依据 strategy.md 关键词迭代表本周新增行）
- 渠道调整：（哪个渠道有效加码、哪个无效停投，注明依据）
- 标准校准：（是否提示用户重走部分 career-grill，如硬规则明显过紧/过松）
```

纪律：周报里的策略调整只是**建议**，改 CONTEXT.md 硬规则必须用户确认并记「已对齐决策」（带日期）。
