# jobhunt-ask —— 这套工具怎么用

你不需要记住任何 skill 的名字。跟 AI 说人话（"我想看看这个岗值不值得投"），它自己会找到对应流程。这张图给你看全貌，也给 AI 当路标。

被问到时：先看用户处在下面哪个位置，把对应的流程名和入口告诉他，再帮他直接开工。设计理念的完整版在仓库的 `docs/DESIGN.md`，用户想深究"为什么这么设计"时带他去读。

## 主线：从零到每天

绝大多数时候，你走的是这条线：

1. **建工作区**（`jobhunt-init`，只做一次）
   说"帮我初始化求职工作区"。AI 检查该装的工具、建好文件夹、放好模板。
   已经有工作区了就跳过；重跑也不怕，它只补缺的，不覆盖你的数据。

2. **梳理求职标准**（`career-grill`，每个方向做一次）
   说"帮我梳理求职方向"。AI 一次一个问题地问你，把"我想找个好工作"逼成一条条能执行的标准，
   写进 CONTEXT.md（你的求职标准手册）。半小时，别糊弄——你随口答的每一句，
   都会变成它之后每天筛掉几十个岗位的依据。

3. **每天跑流水线**（`jobhunt-daily`，天天用）
   说"处理今天的求职"。查新岗位 → 按你的标准筛 JD、评级 → 列清单等你确认 → 你投递 → 记台账 → 出日报。
   这就是日常的全部。投出回应了、约面试了，走下面岔路里的"面试准备"。

## 岔路：什么时候离开主线

- **对行情没底 / 很久没面试、不知道市场价和自己值多少**
  → 做一次市场调研（`market-mapping`）。说"帮我盘一下 XX 岗的市场"。
  它会拉真实市场数据告诉你：这岗需求有多少、薪资什么水位、技能关键词是什么、
  哪些公司在招、你的标准卡得合不合理。
  和每日流水线的区别：流水线是每天的增量动作，调研是一次性的深度摸底。

- **要投某个重要岗位之前**
  → 简历定制（`resume-tailor`）。说"按这个 JD 帮我改简历"。
  AI 对照 JD 重组你的真实经历、对齐措辞，定制稿存进 `runtime/resumes/`，
  **外发前必经你逐字确认**。红线：只重组真实经历，绝不编造。

- **有面试了 / 面试完要复盘**
  → 面试准备（`interview-prep`）。说"帮我准备这家的面试"或"帮我复盘今天的面试"。
  公司调研、问答库、复盘记录都进 `03-interview/` 面试档案，一公司一文件。

- **筛了几轮，推的岗全不想去 / 池子里根本没有这种岗**
  → 大概率标准歪了。带着 `02-jobs/job-ledger.csv` 台账数据回去重新梳理（`career-grill`），
  重点过硬门槛和命脉卖点两块。

## 三个日常习惯

1. **一天一个新会话**；梳理方向也是一个方向一个会话。AI 的对话越长判断越钝，
   而你的数据都在文件里，新会话什么都不丢。
2. **投递授权只管当天**。你说"合适的直接投"，它今天放开手、投了什么逐个报，明天要重新授权。
3. **所有数据就在你的工作文件夹里**：标准是 CONTEXT.md，岗位台账是 `02-jobs/job-ledger.csv`，
   日报在 `runtime/reports/`，定制简历在 `runtime/resumes/`。备份整个文件夹 = 备份一切。

## 常见问题

- **没有 CLI 会不会影响？** 不影响。手动粘贴模式完整可用：你从 Boss直聘/猎聘 App 或网页复制
  岗位描述粘贴给 AI，AI 照常筛选、评级、记台账、出日报；投递永远由你自己在 App 里完成。
- **换了 AI 工具？** 不影响。用新工具打开同一个文件夹，一切照旧。
- **AI 会不会替我乱投简历？** 永远不会。红线写死了：**绝不自动投递、打招呼或发消息给 HR**——
  投递按钮它碰不了，它只能列清单等你拍板。
- **AI 会不会帮我"优化"经历？** 红线写死了：**绝不编造简历和面试内容**——不虚构公司、项目、职位、数字；
  简历定制只做真实经历的重组、取舍与措辞对齐。
- **想改标准？** 直接说"薪资下限改一下"之类，AI 会更新 CONTEXT.md 并在「已对齐决策」记一条带日期的变更。
- **AI 干活的依据是什么？** 只有你文件夹里的 CONTEXT.md 和对内策略笔记
  （`01-profile/_internal/strategy.md`）。它说的标准和文件不一致时，以文件为准，让它重读。
